Making a GPU simulator tell the truth

// the problem

Accel-Sim correlates simulated performance counters against hardware measured by NVIDIA’s profiler. If a counter is wrong, every paper downstream of it is wrong too. Two things were in the way when I started.

First, PTX-mode simulation was simply broken on every CUDA 11+ toolchain — a parser bug meant you could not run the front end at all on a modern install. Second, on the traces that did run, simulated L1-to-L2 write traffic came in roughly 4× higher than hardware, and nobody had explained the gap.

// what I did

1. Unblocked PTX mode

Fixed the Accel-Sim/GPGPU-Sim parser so PTX-mode simulation runs on all CUDA 11+ toolchains, and added an L2 write-hit counter directly comparable to the profiler’s. Both merged upstream.

2. Killed two correctness bugs

Root-caused a SIGSEGV in the FP64 pipeline model: an out-of-bounds index whenever a functional unit’s initiation interval exceeds its latency. Separately, fixed a correlation bug that mis-attributed local-memory traffic, which alone moved one benchmark’s L2 write error from −94.0% to +2.6%.

3. Explained the 4× write inflation

Hypothesised that the hardware merges writes on the L1-to-L2 path and the model does not. Wrote a microbenchmark to isolate and confirm the merging mechanism, then prototyped a merge buffer in the simulator and re-ran the full correlation suite.

// results

Across 32 benchmarks the merge buffer cut mean L2 write error from 19.48% to 2.40% and L2 write-hit error from 19.10% to 2.33%. 19 benchmarks came out bit-identical to before, and the worst collateral change anywhere else was −0.2% — the fix is targeted, not a global fudge factor.

// next

Ongoing. The merge buffer is a prototype, not a faithful model of the hardware structure — the next step is pinning down its real capacity and eviction policy, then extending the same treatment to the read path.
